# 보안과 의존성 적용 범위

## 애플리케이션 경계

클라이언트 검색·정렬 필드의 허용 목록으로 DTO를 사용하세요. 클라이언트의 전체 조건식 뒤에 서버에서 확인한 테넌트·접근 권한 조건을 적용하세요. 검색 기반 수정·삭제는 조건에 맞는 모든 엔티티를 처리하며 조건이 비어 있으면 전체 테이블을 대상으로 합니다. 쓰기 권한을 명시적으로 검사하세요.

라이브러리는 조건 구조와 값을 검증하고 페이지 크기를 제한하며 SQL 값의 문자열 결합 대신 Criteria 조건을 사용합니다. 요청 본문 크기, 문자열 길이, 요청 빈도, 트랜잭션·쿼리 제한 시간, 로그 정책, 응답 필드 노출은 애플리케이션에서 관리해야 합니다. 제한 없는 요청으로 서버 조회 경로를 지정하지 마세요.

## 의존성 검사 기준: 2026년 10월 30일

Boot 4 계열은 Spring Framework 7.0.10을 사용하며, 실제 해석한 Maven 의존성을 OSV로 검사했을 때 취약점이 보고되지 않았습니다. npm 도구에서도 알려진 취약점이 보고되지 않았습니다. 검사 결과는 해당 버전과 날짜를 기준으로 하며, 알려지지 않은 취약점이나 이후 공지까지 보장하지 않습니다.

Boot 3 계열은 Boot 3.5.16 호환성을 위해 Spring Framework 6.2.19를 유지합니다. Tomcat은 10.1.61, Hibernate Validator는 8.0.6.Final로 갱신합니다. 공개 6.2.19 의존성에는 다음 Spring Framework 공지 두 건이 남아 있습니다.

| 공지 | 애플리케이션의 적용 조건 | 공급사 심각도 |
| --- | --- | --- |
| [CVE-2026-47884](https://spring.io/security/cve-2026-47884/) | `XsltView`, 뷰 렌더링을 위한 `/**` 매핑, 명시하지 않은 뷰 이름 | 중간 |
| [CVE-2026-47890](https://spring.io/security/cve-2026-47890/) | 공격자가 제어하는 데이터를 다른 사용자에게 보내는 SSE 뷰 조각 전송 | 낮음 |

Searchable JPA는 XSLT 뷰나 SSE 뷰 조각 엔드포인트를 구성하지 않습니다. 사용하는 애플리케이션에서 별도로 구성할 수 있으므로 해당 조건을 확인해야 합니다. 애플리케이션의 별도 엔드포인트는 일반 검색 테스트와 별도로 보안 검사를 해야 합니다.

Spring은 두 공지의 수정 버전으로 **유료 Enterprise Support의 6.2.20**, 또는 **공개 7.x 계열의 7.0.9 이상**을 안내합니다. 이 프로젝트의 공개 빌드에는 유료 저장소 접근 권한이 포함되지 않습니다. 사용 권한이 있는 애플리케이션은 모든 Spring Framework 모듈을 지원하는 수정 버전으로 맞추고 통합 검사를 실행할 수 있습니다. 라이브러리 2.x 계열로 이동하려면 애플리케이션도 Boot 4로 전환해야 합니다. 유지보수 빌드에서 Spring 6을 Spring 7로 자동 교체하지 않습니다.

## 검사 재현

애플리케이션의 BOM이나 명시적 버전으로 의존성이 바뀔 수 있으므로 실제 해석한 버전을 확인하세요.

```bash
./gradlew :searchable-jpa-core:dependencies --configuration runtimeClasspath
./gradlew :searchable-jpa-core:dependencyInsight --dependency spring-webmvc --configuration runtimeClasspath
npm audit
```

최신 취약점 검사기로 실제 의존성 좌표를 조회하고 공급사 공지의 적용 조건을 확인하세요. H2 통합·호환성 테스트와 별도로 운영 데이터베이스 및 애플리케이션 설정을 검사해야 합니다.
